# 首尾帧与中间关键帧

## 方式 A：直接连接首尾图（已实跑）

在 `MiniMaxH3ImageToVideo` 连接 `first_frame` 与可选 `last_frame`。首帧锚定第 0 帧；尾帧锚定对齐后第 N−1 帧。`length=73` 时是 0 和 72，不是 73。

首帧和尾帧可以是同一张图片：我们十套服装短片这样引导“比心 → 张手 → 回到比心”。这能帮助收尾接近，但不保证无缝循环，仍须检查两端姿势、头发、服饰与曝光。

两张图不同时，尽量保持同一人物、相同服饰、背景和画幅，描述中间如何走到结束姿势。跨度过大会增加变形、跳变风险。

本机实现中，直接首帧会拉伸到目标画幅，尾帧会中心裁切；先准备相同比例的输入，避免人物被拉宽或脚被截掉。

## 方式 B：串联 AddGuide（已实跑首尾；中间帧待测）

```text
H3 conditioning → AddGuide(frame_idx=0, image=A)
                → AddGuide(frame_idx=72, image=A) → BasicGuider → sampler
H3 latent ───────→ 两个 AddGuide 的 latent，以及 sampler 的 latent_image
Video VAE ───────→ 两个 AddGuide 的 vae
```

实际文件：[guide-first-last-api.json](../workflows/guide-first-last-api.json)。`positive` 要串联，不能把第二个节点直接接回原始 conditioning，否则第一个引导不会传下去。

本机源码允许负索引：`-1` 是末帧，`-2` 是倒数第二帧。实际归档使用明确的 72；若改用 -1，应重新运行核验。

中间姿势方案：再串联 `frame_idx=36` 的 AddGuide，并接入该时刻图片。所有索引从 0 开始；在 24fps 下，第 36 帧时间戳约 1.5 秒。此方案由本机节点接口支持，但本仓库没有中间帧实跑成片。

## 引导短片与延长（接口已核对，未实跑）

AddGuide.image 可以输入多帧图像批次。本机实现把不足 5 帧的批次当作单图；其余向下裁到 5、22、39…即 17k+5 帧。引导片段必须装得进剩余时间。与生成总帧数的“向上对齐”不同。

可将上一段末尾短片作为下一段开头引导，采样完成后裁掉重叠部分再拼接。身份、灯光、动作速度以及音轨连接都要另验，不能把这个规划标成已实现的无缝长视频。

关键帧是采样条件，不是把原图硬贴回成片；当前工作流的 `denoise` 不用于调节引导强弱。
